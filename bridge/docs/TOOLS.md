# Tool reference

Generated by `bridge/tools/gen_tool_docs.py` from the server's own tool list; do not edit by hand. Run `python tools/gen_tool_docs.py` from `bridge/` after changing a tool. 138 tools in 14 groups.

Every tool answers with the same envelope: `ok`, `outcome`, `data` (the answer), and on failure `error` with a `code`, a `message` and a `recovery` line that says what to do next. **Kinds:** a read tool changes nothing; an act tool changes the running game, needs `fnv.engine_control` set to `full` and is journaled (`fnv_journal`, `fnv_undo`); a control tool changes files or starts and stops the game. A tool with several kinds takes the strongest kind of its actions.

Where to start: [docs/README.md](README.md). How the tools reach the game: [FNV-LIVE-TOOLS.md](FNV-LIVE-TOOLS.md).

### fnv_status

**Kind:** read · **Toolset:** game

Is the game running, and in which phase (not_running, starting, main_menu, loading, in_game, in_menu, paused_menu)? Gives the cell, the loaded plugins with their load-order index, the engine companion's ping (frame counter, ms since the last frame) and whether a crash log was written since launch.

No parameters.

Example:

```json
{"tool": "fnv_status", "arguments": {}}
```

### fnv_setup_check

**Kind:** read · **Toolset:** game

Is this machine ready for the fnv_* tools? Checks the game build, xNVSE, the MO2 dev instance and its NVSE executable, JIP LN NVSE, the crash logger, bAlwaysActive, Zig, the engine companion (installed, up to date), the engine map, the optional unpacked exe and full control; each with what to do when it is missing.

No parameters.

Example:

```json
{"tool": "fnv_setup_check", "arguments": {}}
```

### fnv_guide

**Kind:** read · **Toolset:** game

Which tool to use for a problem. list: the guides (for example "the game crashed", "a script does not run"). topic: one guide, by name or by words that describe the problem: tools in order, what each answer means, known traps, checks that prove the fix. find: search the tool names and descriptions and the guides ("which tool for X"). engine: search the saved engine research notes (fnv.research_dir or FNV_RESEARCH_DIR) and the recorded engine facts for how the engine does something. Needs no running game.

**Actions:**

- `list` (default): The guides, with a one-line summary each.
- `topic`: One guide, by name or by words that describe the problem.
- `find`: Search the tool names, descriptions and guides.
- `engine`: Search saved engine research notes and the recorded engine facts.

| Parameter | Type | Allowed | Default | What it is |
| --- | --- | --- | --- | --- |
| `action` | string | `list`, `topic`, `find`, `engine` | `"list"` | list (default) shows the guides; topic gives one guide; find searches tools and guides; engine searches saved research notes and recorded engine facts. |
| `words` | string | up to 300 characters |  | For topic: a guide name (crash, start) or words describing the problem. For find and engine: the words to search for. Not used by list. |
| `limit` | integer | 1 to 100 | `20` | For find and engine: maximum results, 1 to 100. Default 20. |
| `offset` | integer | 0 or more | `0` | For find and engine: results to skip, for paging. Default 0. |
| `brief` | boolean |  | `false` | For find and engine: if true, each row has only its kind, name, action and example call (find) or file, line and heading (engine). |

Example:

```json
{"tool": "fnv_guide", "arguments": {"action": "topic", "words": "the game crashed"}}
```

### fnv_companion_install

**Kind:** control · **Toolset:** game

Build the fnvmcp engine companion (C, Zig 0.14.1 from fnv.zig or FNV_MCP_ZIG) and install it, or remove it (uninstall). target: mo2 puts it into the dev profile as the MO2 mod "fnvmcp engine companion"; game puts it into the game folder's Data\NVSE\Plugins, so it loads however the game starts (Steam's Play button, nvse_loader.exe), with a receipt and a backup of a file it replaces; auto is mo2 when the project names an MO2 instance, and otherwise asks for target=game. uninstall disables the MO2 mod, or removes the file from the game folder when it is the one this tool installed. The game must be closed; it loads at the next start.

**Actions:**

- `install` (default): Build the engine companion with Zig and install it into the dev profile or the game folder.
- `uninstall`: Turn the companion mod off, or remove the file this tool put into the game folder.

| Parameter | Type | Allowed | Default | What it is |
| --- | --- | --- | --- | --- |
| `target` | string | `auto`, `mo2`, `game` | `"auto"` | Where to install: mo2 (the dev profile, as its own MO2 mod), game (the game folder's Data\NVSE\Plugins) or auto (default: mo2 when the project names an MO2 instance, else it asks for game). |
| `action` | string | `install`, `uninstall` | `"install"` | install (default) builds the companion with Zig and installs it; uninstall turns the MO2 mod off or removes the file this tool put into the game folder. |

Example:

```json
{"tool": "fnv_companion_install", "arguments": {"target": "mo2"}}
```

### fnv_game

**Kind:** control · **Toolset:** game

The game process. launch: start Fallout: New Vegas and wait until it is ready: at the main menu, in a save (loaded by the companion, no clicks), or in a cell via coc; refuses when the game already runs; returns a timeline of the startup. via: mo2 runs it through the MO2 profile named in fnv.mo2_profile (and its saves); direct runs nvse_loader.exe (else FalloutNV.exe) from the game folder, as Steam's Play button does; auto (the default) is mo2 when the project names an MO2 instance, else direct. A game you started yourself needs no launch: the tools attach to it (fnv_status). On the direct install a save start needs fnv.allow_direct_install_changes. quit: the console's qqq first, then closing its window, then (force=true) terminating it; a game the bridge did not start is quit only with engine_control full. restart: quit (if running) and launch again; use after installing plugins or DLLs. timeout_seconds: launch and restart 20 to 600 (default 240), quit 5 to 120 (default 20). fnv_session start also launches, with a setup check and a journal scope.

**Actions:**

- `launch`: Start the game and wait until it is ready at the menu, in a save or in a cell.
- `quit`: Quit the game: console quit, then closing the window, then terminating if forced.
- `restart`: Quit if running, then launch again.

| Parameter | Type | Allowed | Default | What it is |
| --- | --- | --- | --- | --- |
| `action` | string | `launch`, `quit`, `restart` | required | launch (start the game and wait until ready), quit, or restart (quit if running, then launch). |
| `start` | string | pattern `^(menu\|continue\|save:[A-Za-z0-9_. \-]{1,120}\|coc:[A-Za-z0-9_]{1,120})$` | `"menu"` | menu \| continue (newest dev save) \| save:<name> \| coc:<cell EditorID> |
| `force` | boolean |  | `true` | For quit: if true (default), terminate the game when the console quit and closing the window do not end it. |
| `timeout_seconds` | integer | 5 to 600 |  | Seconds to wait. launch and restart: 20 to 600, default 240. quit: 5 to 120, default 20. |
| `via` | string | `auto`, `mo2`, `direct` | `"auto"` | For launch and restart: mo2 (the MO2 dev profile), direct (nvse_loader.exe in the game folder) or auto (default: mo2 when the project names an MO2 instance). |

Example:

```json
{"tool": "fnv_game", "arguments": {"action": "launch", "start": "continue"}}
```

### fnv_session

**Kind:** control · **Toolset:** game

One call to be ready and one to finish. start: check the setup, launch the game when it is not running (at start: menu, continue, save:<name> or coc:<cell>), wait until it is loaded and simulating, turn on capture (script errors, engine warnings, crash context), optionally a deterministic run, and open a journal scope. mark: a named point (label) that fnv_health and the warning log report from. end: revert this session's journal changes, return one report, and quit the game when quit_game is true. status: the session, cheaply. Starting the game and changing the warning setting need the game closed or a restart to take effect.

**Actions:**

- `start`: Check the setup, launch if needed, wait until loaded, turn on capture, open a journal scope.
- `mark`: A named point that the health and warning reports count from.
- `end`: Revert the session's changes and give one report; quit_game quits.
- `status`: The session, cheaply.

| Parameter | Type | Allowed | Default | What it is |
| --- | --- | --- | --- | --- |
| `action` | string | `start`, `mark`, `end`, `status` | required | start readies the game and opens a session, mark records a named point, end reverts the session's changes and reports, status shows the session cheaply. |
| `start` | string | pattern `^(menu\|continue\|save:[A-Za-z0-9_. \-]{1,120}\|coc:[A-Za-z0-9_]{1,120})$` | `"continue"` | menu \| continue (newest dev save) \| save:<name> \| coc:<cell EditorID> |
| `label` | string | up to 60 characters |  | For action=mark: the name of the point that fnv_health and the warning log report from. |
| `deterministic` | boolean |  | `false` | For action=start: if true, run deterministically (fixed frame step, seeded random numbers). Default false. |
| `quit_game` | boolean |  | `false` | For action=end: if true, quit the game after the report. Default false leaves it running. |
| `timeout_seconds` | integer | 20 to 600 | `240` | For action=start: seconds to wait for the game to launch, load and start simulating. Default 240. |

Example:

```json
{"tool": "fnv_session", "arguments": {"action": "start", "start": "continue"}}
```

### fnv_health

**Kind:** read · **Toolset:** game

What is abnormal since the last session mark (fnv_session mark, or the session start): script errors, engine warnings by category, new crash files, frame time against the session start, and the live object count (NiRefObject) against the session start. Returns ok true, or a short list where each item names the tool to call next. Needs an open session (fnv_session start).

No parameters.

Example:

```json
{"tool": "fnv_health", "arguments": {}}
```

### fnv_window

**Kind:** control · **Toolset:** game

The game window and the user's mouse: release_mouse switches the game's DirectInput mouse to non-exclusive background mode on its own window, so the cursor is free while the game keeps running; capture_mouse puts exclusive mode back; unpause closes the pause menu (it opens when the window loses focus). persist=true writes bBackground Mouse=1 to the dev profile's Fallout.ini so every launch leaves the mouse free (false undoes it). Works without the game for persist.

**Actions:**

- `status` (default): The game window and mouse mode.
- `release_mouse`: Free the mouse while the game keeps running.
- `capture_mouse`: Give the mouse back to the game.
- `unpause`: Close the pause menu.

| Parameter | Type | Allowed | Default | What it is |
| --- | --- | --- | --- | --- |
| `action` | string | `status`, `release_mouse`, `capture_mouse`, `unpause` | `"status"` | status (default), release_mouse (free the cursor while the game runs), capture_mouse or unpause (close the pause menu). |
| `persist` | boolean |  |  | If true, write bBackground Mouse=1 to the dev profile's Fallout.ini so every launch leaves the mouse free; false removes it. Omitted changes nothing. |

Example:

```json
{"tool": "fnv_window", "arguments": {"action": "release_mouse"}}
```

### fnv_spec

**Kind:** control · **Toolset:** game

Build a plugin (.esp) from the project's JSON spec, offline (no GECK, no game). validate [spec]: dry run of the project spec, or of an inline spec object: structure, references via the master index, meshes and textures; writes nothing. build: writes the plugin and a receipt (FormIDs, references, validation) into the build folder and keeps FormIDs stable across builds; refuses when validation fails. A script is emitted compiled once fnv_scripts_compile has cached it from the game. inspect [which=build|installed]: masters, record counts and cells of the build or of the installed copy (the MO2 dev profile mod, else Data). lookup query [record_type] [limit]: records by EditorID in the spec and the indexed masters, with the "@EditorID" reference to use in the spec. fields [record_type]: the named fields a type takes in a record's "set" (ARMO value, weight...; lists such as LVLI entries); "template": "@EditorID" starts a record from a master's, "override": true changes a master record in place. Install a build with fnv_install.

**Actions:**

- `validate`: Check the project spec or an inline spec; writes nothing.
- `build`: Write the plugin and a receipt into the build folder.
- `inspect`: Masters, record counts and cells of the build or the installed copy.
- `lookup`: Find records by EditorID in the spec and the indexed masters.
- `fields`: The named fields and lists a record type takes in "set".

| Parameter | Type | Allowed | Default | What it is |
| --- | --- | --- | --- | --- |
| `action` | string | `validate`, `build`, `inspect`, `lookup`, `fields` | required | What to do: validate (dry run, writes nothing), build (write the plugin and receipt), inspect (summarise a plugin on disk), lookup (find records by EditorID for the spec), fields (the named fields a record type takes in "set"). |
| `spec` | object |  |  | For action=validate: an inline spec object to check instead of the project spec file. Omitted checks the project spec. |
| `which` | string | `build`, `installed` | `"build"` | For action=inspect: build (default) is the last build; installed is the copy fnv_install put in the MO2 dev profile, else the one in Data. |
| `query` | string | up to 100 characters |  | For action=lookup: part of an EditorID (2 to 100 characters) to find in the spec and the indexed masters. |
| `record_type` | string | pattern `^[A-Z_]{4}$` |  | For action=lookup: keep only records of this four-letter type, such as STAT or MISC. For action=fields: the type whose named fields to list (ARMO, LVLI, TERM...). |
| `limit` | integer | 1 to 100 | `25` | For action=lookup: maximum master records returned. Default 25. |

Example:

```json
{"tool": "fnv_spec", "arguments": {"action": "validate"}}
```

### fnv_install

**Kind:** control · **Toolset:** game

Install a built .esp/.esm into the dev profile as its own MO2 mod (mods/<name>/), enable the mod and the plugin. On the direct install (no MO2) it goes into the real Data folder and plugins.txt instead, only with fnv.allow_direct_install_changes (mod_name is not used there). The game must be closed. A previous copy (and plugins.txt) is backed up.

| Parameter | Type | Allowed | Default | What it is |
| --- | --- | --- | --- | --- |
| `plugin_path` | string | up to 1000 characters | required | Path of the built .esp or .esm file to install, such as the plugin fnv_spec build wrote. |
| `mod_name` | string | up to 80 characters |  | MO2 mod folder name to install into. Default: the plugin's name. Not used on the direct install. |

Example:

```json
{"tool": "fnv_install", "arguments": {"plugin_path": "build/HelloWasteland.esp"}}
```

### fnv_scripts_compile

**Kind:** control · **Toolset:** game

The last build must be installed and loaded (its forms must exist). Each entry is checked with the builder's verification and records an in-game provenance. Scripts with Quest.variable references cannot be compiled in game.

| Parameter | Type | Allowed | Default | What it is |
| --- | --- | --- | --- | --- |
| `only` | string[] | each: up to 128 characters |  | Only compile these scripts of the project spec, by EditorID. Omitted compiles all of them. |

Example:

```json
{"tool": "fnv_scripts_compile", "arguments": {}}
```

### fnv_author

**Kind:** control · **Toolset:** game

Authoring. export: the session's created forms and placed references as a plugin spec part (records by EditorID, objects of a cell) in the bridge state folder, to merge into the project spec. check plugin: missing files, conflicts and engine warnings. scaffold kind name: a starting project (spec, a smoke test, readme). package plugin [module] [build] [version]: a release zip with the plugin, its loose files, the fnv_plugin_build module and a manifest; refused if a file holds decompiled code or a path of this machine.

**Actions:**

- `export`: This session's created forms and placed objects as a spec part to merge into the project spec.
- `check`: Missing files, conflicts and the engine warning summary of a plugin, in one report.
- `scaffold`: A starting project of a kind: spec, smoke test and readme.

| Parameter | Type | Allowed | Default | What it is |

### fnv_place

**Kind:** act · **Toolset:** game

Place things in the running game; every placement is journaled for fnv_author export. at base: at position, or near a ref (+ offset), or 150 units in front of the player; rotation in degrees, scale, snap=true drops it on the surface below. Snap rests the bottom of its bounds on the ground under its whole footprint: rest=low (default) on the lowest ground, so no corner floats and the uphill side sinks; centre (the ground under its origin) or high. The result's footprint says how much sank or floats, overhangs and a warning; steep ground suggests a heading, and ground rising more than its height is refused (TOO_STEEP). array base: shape row, grid (columns) or circle (radius), count, spacing, from position or the player. nudge ref offset=[dx,dy,dz] (local=true in its own axes), rotate ref rotation=[dx,dy,dz] degrees added, scale ref scale. snap ref [align] [rest]: onto the surface below (align=true also tilts it to the slope at its heading, fitted over its footprint). check ref: floating or sinking, over its footprint. list: what this session placed. remove: one placed ref, or all of them. at with export=false: a test placement left out of fnv_author export (an enemy for a test): base near a ref (default the player) with PlaceAtMe, count copies, distance and direction (0 front, 1 back, 2 left, 3 right); fnv_undo disables and deletes them. fnv_world_edit moves, rotates, scales and deletes any ref, not only this session's placements.

**Actions:**

- `at`: Place a base form at a position, near a reference, or in front of the player.
- `array`: Place several copies in a row, grid or circle.
- `nudge`: Move a placed reference by an offset.
- `rotate`: Turn a placed reference by angles in degrees.
- `scale`: Set the scale of a placed reference.
- `snap`: Drop a reference onto the surface below its footprint; align tilts it to the slope.
- `check`: Is a reference floating or sinking, over its footprint.
- `list`: What this session placed.
- `remove`: Remove one placed reference, or all of them.

| Parameter | Type | Allowed | Default | What it is |
| --- | --- | --- | --- | --- |
| `action` | string | `at`, `array`, `nudge`, `rotate`, `scale`, `snap`, `check`, `list`, `remove` | required | at places a base form, array places several, nudge/rotate/scale change a placed ref, snap drops it on the surface, check tests floating or sinking, list shows placements, remove deletes one or all. |
| `base` | string | up to 200 characters |  | player, crosshair, form id (0x14), Plugin.esp:LOCALID or EditorID |
| `ref` | string | up to 200 characters |  | player, crosshair, form id (0x14), Plugin.esp:LOCALID or EditorID |
| `position` | number[3] |  |  | [x, y, z] in game units |
| `near` | string | up to 200 characters |  | player, crosshair, form id (0x14), Plugin.esp:LOCALID or EditorID |
| `offset` | number[3] |  |  | [x, y, z] in game units |
| `rotation` | number[3] |  |  | [x, y, z] angles in degrees |
| `scale` | number | above 0, up to 10 |  | Scale factor. For action=at it sets the new object's scale; for action=scale it is the new scale of ref. |
| `shape` | string | `row`, `grid`, `circle` |  | For action=array: row, grid or circle layout. |
| `count` | integer | 1 to 100 |  | For action=array: how many objects to place. |
| `spacing` | number | above 0, up to 5000 |  | For action=array: distance between neighbouring objects in game units. |
| `columns` | integer | 1 to 50 |  | For action=array shape=grid: number of columns per row. |
| `radius` | number | above 0, up to 10000 |  | For action=array shape=circle: circle radius in game units. |
| `snap` | boolean |  | `false` | If true, drop the placed object onto the surface below it (the bottom of its bounds on the ground under its footprint). |
| `local` | boolean |  | `false` | For action=nudge: if true, the offset is in the object's own axes instead of world axes. |
| `align` | boolean |  | `false` | For action=snap: if true, also tilt the object to the slope of the ground under its footprint at its heading. |
| `rest` | string | `low`, `centre`, `high` |  | For snapping (at/array with snap=true, and action=snap): low (default) rests the bottom on the lowest ground under the footprint so no corner floats; centre on the ground under its origin; high on the highest ground so nothing sinks. |
| `export` | boolean |  | `true` | For action=at: false makes a test placement (PlaceAtMe near a ref) that fnv_author export leaves out. Default true. |
| `distance` | integer | 0 to 10000 |  | For action=at with export=false: how far from the near ref to place, in game units. |
| `direction` | integer | 0 to 3 |  | For action=at with export=false: 0 front, 1 back, 2 left, 3 right of the near ref. |

Example:

```json
{"tool": "fnv_place", "arguments": {"action": "at", "base": "MyWorkbench", "near": "player", "snap": true}}
```

### fnv_world_edit

**Kind:** act · **Toolset:** game

Edit the live world with the functions the console commands use: move (position [x, y, z], null keeps an axis), rotate (degrees), scale, transform (any of them), enable, disable (fade), delete (MarkForDelete), duplicate (PlaceAtMe of the same base, distance, count), weather (force a weather form, or "release"), imagespace / imagespace_stop (an image-space modifier at a strength). **Actions:**

- `disable`: Disable a reference, optionally fading out.
- `delete`: Mark a reference for deletion.
- `duplicate`: Place copies of the same base next to it.
- `weather`: Force a weather, or release the override.
- `imagespace`: Start an image-space modifier.
- `imagespace_stop`: Stop an image-space modifier.

### fnv_atlas

**Kind:** act · **Toolset:** naming

Which functions run for which game action, measured with the probe set (install it with fnv_probe first). actions: the scripted action library. run: for each action, idle segments and segments doing it 1, 2 and 4 times (reps repetitions), counters read before and after each; a fit per function gives calls per action (per_unit) or 'only while acting' (with_action). Results go to state/atlas.sqlite. runs: the runs stored. function: every fit and caller recorded for one function. action: the functions an action runs (kind, statuses e.g. ['unnamed'], exclusive: no other action runs them; console machinery left out unless asked). import_frida: load fnvsym's Frida trace file (path) as a run of its own.

**Actions:**

- `actions` (default): The scripted game actions the atlas can measure.
- `run`: Measure actions against the probe counters and fit calls per action for every function.
- `runs`: The stored runs.
- `function`: Every fit and caller recorded for one function.
- `action`: The functions one game action runs, filtered by kind, status or exclusiveness.
- `import_frida`: Load a Frida trace file as a run of its own.

| Parameter | Type | Allowed | Default | What it is |
| --- | --- | --- | --- | --- |
| `action` | string | `actions`, `run`, `runs`, `function`, `action`, `import_frida` | `"actions"` | What to do: actions (list scripted actions), run (measure actions), runs (stored runs), function (fits for one function), action (functions an action runs), import_frida (load a Frida trace file). |
| `actions` | string[] |  |  | For action=run: names of the scripted actions to measure. Omitted means the default set from the action library. |
| `reps` | integer |  | `2` | For action=run: how many times each measurement is repeated. Default 2. |
| `doses` | integer[] |  |  | For action=run: how many times the action is done in each segment, for example [1, 2, 4]. Omitted uses each action's own default. |
| `name` | string |  |  | For action=action: the name of the game action whose functions to list. |
| `function` | string |  |  | For action=function: the function (name or address) whose recorded fits and callers to show. |
| `kind` | string |  |  | For action=action: keep only fits of this kind, per_unit (calls per action) or with_action (only while acting). |
| `run` | integer |  |  | For action=action: the run number to read. Omitted means the latest run that measured the action. |
| `statuses` | string[] |  |  | For action=action: keep only functions with these naming statuses, for example ['unnamed']. |
| `exclusive` | boolean |  | `false` | For action=action: if true, keep only functions that no other action runs. |

### fnv_name_oracle

**Kind:** act · **Toolset:** naming

Does the function return a value the game already knows, on the same objects? run: its results - from probe samples, or by calling it on the references, base forms, quests, cells, worldspaces and packages around the player when its machine code is proven free of side effects (purity) - are compared with script commands (GetLevel, GetScale, GetAV x, GetRace, GetStage, GetCellFlag n, ...) and form header fields. A match needs >= 20 objects, no mismatch, a chance of matching by a random pairing <= 1e-6, and no shuffled pairing matching (PROOF 4.2). purity: the side-effect check alone. calibrate: the method run blind on proven getters and scored after (state/oracle_calibration_*.json). sweep: run it on every not-proven pure getter whose this class is known.

**Actions:**

- `run` (default): Compare a function's results with values the game already knows on the same objects.
- `purity`: Check that a function writes nothing but its own stack.
- `calibrate`: Run the method blind on proven getters and score it.
- `sweep`: Run it on every unproven pure getter.

| Parameter | Type | Allowed | Default | What it is |
| --- | --- | --- | --- | --- |
| `action` | string | `run`, `purity`, `calibrate`, `sweep` | `"run"` | run compares a function's results with known script commands and form fields; purity only checks it is free of side effects; calibrate runs the method blind on proven getters; sweep runs it on every unproven pure getter. Default run. |
| `function` | string |  |  | The engine function to test. Needed for run and purity. |
| `mode` | string | `auto`, `call`, `sampled` | `"auto"` | For run: call invokes the function on nearby objects, sampled uses recorded probe samples, auto picks (calls it when proven side-effect free). Default auto. |
| `harvest` | integer |  |  | For run and sweep: optional number controlling how many samples are harvested; null uses the default. |
| `radius` | number |  | `8000.0` | Distance around the player, in game units, within which objects are gathered. Default 8000. |
| `limit` | integer |  | `400` | For calibrate and sweep: maximum number of functions to process. Default 400. |

Example:

```json
{"tool": "fnv_name_oracle", "arguments": {"action": "purity", "function": "0x0086A4B2"}}
```

### fnv_name_test

**Kind:** act · **Toolset:** naming

Experiments on one function (PROOF 4.2): test runs a hypothesis {function, intervention {action skip|result|arg, value, arg}, panel (a battery panel name) or target/setup/trigger/observe/expect, predict blocked|normal, reps >= 3}: each repetition does the action without the change (control) and with it; confirmed when the control shows the normal effect and the change the predicted one every time. battery: skip each function during each panel (set scale, disable, enable, set angle, destroyed, ghost, set/damage actor values on an NPC, a creature and the player, XP, items) - the panels it blocks identify it, blind; scored against names afterwards. panels: the battery.

**Actions:**

- `test` (default): Run one experiment hypothesis with a control in every repetition.
- `battery`: Skip each function during each panel; the panels it blocks identify it.
- `panels`: The battery panels.

| Parameter | Type | Allowed | Default | What it is |
| --- | --- | --- | --- | --- |
| `action` | string | `test`, `battery`, `panels` | `"test"` | test (default) runs one hypothesis, battery skips each function during each panel, panels lists the battery panels. |
| `hypothesis` | object |  |  | For test: {function, intervention {action skip\|result\|arg, value, arg}, panel or target/setup/trigger/observe/expect, predict blocked\|normal, reps >= 3}. |
| `functions` | string[] |  |  | For battery: the functions to test, by name or address. Omitted uses the built-in key set. |
| `panels` | string[] |  |  | For battery: the panel names to run (from action=panels). Omitted runs every panel. |
| `reps` | integer |  | `3` | For battery: repetitions of each run, each with a control. Default 3. |

Example:

```json
{"tool": "fnv_name_test", "arguments": {"action": "panels"}}
```
